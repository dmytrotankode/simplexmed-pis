## 4. Що зробити оператору перед подачею

1. **Завантажити новий `pis/deploy/redirect-ehealth.js` на https://simplex-med.com/js/redirect-ehealth.js.** Це критично для перевірки безпеки. У чинній версії є відкрите перенаправлення: підроблений `state` може відправити код авторизації на сторонній домен. Нова версія приймає лише відносний шлях. Маршрути МІС (app2, cabinet) у ній не змінено. Сумісність зі state кабінету перевіряє `pis/tests/redirect_return_compat_test.js`.
2. **Створити поштові скриньки** `support@simplex-med.com` (вказана в повідомленнях про помилки за Додатком 1) і `privacy@simplex-med.com` (вказана в Політиці конфіденційності).
3. **Перевірити вхід і підпис реальним тестовим КЕП** на PreProd (веб і Android): вхід, реєстрація, подання та підпис декларації, зміна даних.
4. **Вирішити, що показує https://my.simplex-med.com до отримання продуктивних ключів.** Зараз там та сама PreProd-система, що й на my-dev. Рекомендовано тимчасову сторінку «Кабінет запрацює незабаром» з Політикою конфіденційності.
5. **Зробити резервну копію ключа підпису застосунку** `/root/.simplexpis/` на сервері збирання. Без нього не вийде оновити застосунок у Google Play.
6. **Подати заявку** на порталі користувачів (крок 4):
   - вказати IP PreProd: 188.245.104.34;
   - прикріпити документи з розділу 1;
   - листом надіслати зашифрований архів із посиланнями з розділу 2 на адресу, вказану на сторінці НСЗУ.

## 5. Після позитивного висновку (кроки 7–8)

- Заява на приєднання до договору і логотип ПІС: PNG 180×100.
- Продуктивні ключі доступу НСЗУ (5 робочих днів).
- Продуктивне середовище:
  - окремий сервер в Україні з доменом my.simplex-med.com;
  - `APP_ENV=prod`, продуктивні `PIS_CLIENT_ID`, `PIS_CLIENT_SECRET`, хости API ЕСОЗ;
  - нова база даних і новий `PIS_TOKEN_KEY`.
- Рекомендовано зареєструвати в НСЗУ redirect_uri на домені кабінету (наприклад, `https://my.simplex-med.com/ehealth/return/my`), щоб не залежати від скрипту на simplex-med.com.
