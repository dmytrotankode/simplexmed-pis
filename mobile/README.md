# SimplexMed ПІС — мобільний застосунок (React Native / Expo)

Код: [`app/`](app/) — Expo SDK 57, React Native 0.86, Expo Router, TypeScript.
Працює з тим самим BFF, що й веб-кабінет (`extra.pisApiBase` у `app.json`, зараз `https://my-dev.simplex-med.com`).

## Що реалізовано

Відповідність перевірено за **чинною** редакцією: ТВ до ПІС v2, наказ НСЗУ № 978 від 08.12.2025
(текст — [`../docs/tv_pis_978.txt`](../docs/tv_pis_978.txt); актуальність — `python pis/tools/check_tz_updates.py`).
Застосунок — КПІС: розділи 3.2 і 3.4 (АПІС, Дія) до нього не належать.

## Huawei

Застосунок не використовує Google Play Services: SecureStore (Keystore), біометрія (BiometricPrompt), Custom Tabs/браузер
і WebView є частиною Android/AOSP, тож той самий APK/AAB працює на Huawei з EMUI / HarmonyOS 2–4 (AppGallery).
Коли з'являться push-сповіщення, знадобиться окремий варіант збірки: FCM для Google Play і HMS Push Kit
(`@hmscore/react-native-hms-push`) для AppGallery — профіль `production-huawei` у `eas.json` для цього вже є.
HarmonyOS NEXT (5+) не запускає Android-застосунки — для нього потрібна окрема збірка (React Native for OpenHarmony).

## Безпека входу

ЕСОЗ не підтримує PKCE, а код повертається через спільний redirect_uri `https://simplex-med.com`. Тому прив'язку до
пристрою робить BFF: state підписаний цілком (середовище, шлях, час, випадкове значення) разом із `code_challenge`,
а `/api/auth/token` для мобільного клієнта приймає код лише з відповідним `code_verifier`. Код і state, перехоплені
іншим застосунком зі схемою `simplexpis://` або через відкритий редирект у старій версії `redirect-ehealth.js`,
обміняти на сесію не можна.

Сторінка `/ehealth/return/app` відкриває застосунок автоматично, а якщо браузер заблокує перехід за схемою без дії
користувача — показує кнопку «Повернутися до застосунку».

### Збірка APK без Android Studio і EAS

[`build-android.sh`](build-android.sh) збирає підписаний release-APK на Linux-сервері (188.245.104.34). Інструменти —
в ізольованій `/opt/android-build` (JDK 17 Temurin, Android SDK 36, build-tools 36.0.0, NDK 27.1, CMake 3.22.1,
Node 22; видаляються одним `rm -rf`). Запуск з обмеженням ресурсів, щоб не заважати сервісам на сервері:

```bash
systemd-run --scope -p MemoryMax=6G -p CPUQuota=400% nice -n 19 ionice -c3 bash /opt/android-build/build-android.sh /opt/android-build/work/app /opt/android-build/out
```

Ключ підпису створюється при першому запуску: `/root/.simplexpis/upload.jks`, паролі — `/root/.simplexpis/signing.env`
(права 600). **Зробіть резервну копію обох файлів**: застосунок, підписаний іншим ключем, не встановиться поверх
наявного, а для Google Play це ключ завантаження.

Альтернатива — EAS (хмара): `npx eas-cli@latest build --profile preview --platform android` (потрібен обліковий запис
Expo). iOS-збірка потребує macOS або EAS і облікового запису Apple Developer.

## Залежність від сервера

- BFF: `env=pis-app` у `/api/auth-url` (повертає `state`), обмін коду з `platform=MOBILE` (повертає `session_token`),
  `Authorization: Bearer <session_token>` для всіх `/api/ehealth/*`; `code_challenge` у `/api/auth-url`
  і `code_verifier` у `/api/auth/token` обов'язкові.
- Повернення працює і з версією `redirect-ehealth.js`, яка зараз розгорнута на simplex-med.com (вона знає `my-dev`),
  і з новою з `pis/deploy/` (перевіряє `pis/tests/redirect_return_compat_test.js`). Нову версію все одно варто
  викласти: стара пропускає код на сторонній хост за state на кшталт `my-dev|@evil.com` (для веб-кабінету це
  ризик фішингу) і не передає помилки сервісу авторизації (`error=`) — при скасуванні входу користувач лишається
  на simplex-med.com і закриває браузер сам.
